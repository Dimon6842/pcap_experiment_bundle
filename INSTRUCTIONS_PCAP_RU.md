# Инструкция к основному эксперименту по PCAP

## 1. Какие исходные данные нужны

Используется открытый набор **UTSA-2021 Low-rate DoS Attack** из официального репозитория авторов:

- [PCAPs_1.zip](https://github.com/utsanetsys/UTSA-2021-Low-rate-DoS-Attack/blob/main/PCAPs_1.zip)
- [PCAPs_2.zip](https://github.com/utsanetsys/UTSA-2021-Low-rate-DoS-Attack/blob/main/PCAPs_2.zip)
- [PCAPs_3.zip](https://github.com/utsanetsys/UTSA-2021-Low-rate-DoS-Attack/blob/main/PCAPs_3.zip)
- [Benign_Only.zip](https://github.com/utsanetsys/UTSA-2021-Low-rate-DoS-Attack/blob/main/Benign_Only.zip)

Для выбранного эксперимента нужны три архива с атакующими записями и архив только с нормальным трафиком. `1Client_PCAPs.zip` относится к отдельному сценарию с одним клиентом и в основную выборку пока не включается.

## 2. Подготовка

1. Скачайте четыре ZIP-архива по ссылкам выше.
2. Поместите их без распаковки в одну папку, например `utsa_pcap_input`.
3. Сохраните `main_pcap_experiment.py` из этого набора рядом с папкой данных.
4. Установите зависимости из `requirements.txt`.

```bash
python -m pip install -r requirements.txt
```

## 3. Сначала проверка временной структуры

Выполните первичный запуск с шагом 0,1 секунды:

```bash
python main_pcap_experiment.py --data-dir utsa_pcap_input --out-dir audit_dt_0_1 --bin-width 0.1
```

Скрипт распаковывает архивы во временной памяти, читает PCAP/PCAPNG, считает TCP SYN-пакеты без ACK, составляет инвентаризацию и проверяет совмещение временных рядов с 200-секундным шаблоном: 100 секунд активной фазы с импульсами длительностью 0,1 секунды и 100 секунд спокойной фазы.

Проверьте файлы:

- `pcap_inventory.csv` — названия, длительность, число пакетов, число TCP SYN без ACK, предполагаемая метка класса и тип канального уровня;
- `labels_template.csv` — таблица для ручной разметки, если по имени PCAP нельзя понять класс;
- `phase_alignment_diagnostics.csv` — фазовое смещение, качество корреляции и доля циклов, согласующихся с общей фазой;
- `series_*.npz` — сохранённые временные ряды для аудита.

Не следует автоматически принимать разметку только по имени. Если `label` в шаблоне пуст, укажите `0` для нормального трафика или `1` для атакующего. Поле `attack_rate` можно заполнить, например, `Syn25`, `Syn50`, `Syn75`; для нормальных файлов укажите `benign`. Затем запустите основной расчёт с параметром `--labels-csv`.

## 4. Основной расчёт

Основной шаг агрегации — 0,01 секунды: импульс 0,1 секунды тогда представлен примерно десятью временными отсчётами.

```bash
python main_pcap_experiment.py --data-dir utsa_pcap_input --out-dir main_dt_0_01 --bin-width 0.01
```

Если требуется ручная разметка:

```bash
python main_pcap_experiment.py --data-dir utsa_pcap_input --out-dir main_dt_0_01 --bin-width 0.01 --labels-csv labels_template.csv
```

После основного расчёта рекомендуется выполнить проверку устойчивости при более грубой агрегации 0,1 секунды в отдельную папку:

```bash
python main_pcap_experiment.py --data-dir utsa_pcap_input --out-dir robustness_dt_0_1 --bin-width 0.1
```

## 5. Что формируется на выходе

- `main_experiment_results.csv` — ROC AUC, 95%-й доверительный интервал, чувствительность (TPR), доля ложных срабатываний (FPR), средняя доля потерянных атакующих импульсных отсчётов `q`, медианная и межквартильная ошибка определения периода;
- `main_experiment_windows.csv` — результаты для каждого временного окна и сценария пропуска;
- `pcap_inventory.csv` — состав обработанной выборки;
- `phase_alignment_diagnostics.csv` — диагностика временной разметки атак;
- `experiment_metadata.json` — параметры, ограничения и seed;
- `series_*.npz` — агрегированные временные ряды.

Сравниваются FFT после линейной интерполяции, FFT после нулевого заполнения и метод Ломба—Скаргла по фактическим временным отметкам. Для каждого метода и сценария порог калибруется по 95-му процентилю нормальных обучающих окон; тестовая часть отделяется хронологически.

## 6. Условия, при которых результаты можно переносить в статью

1. В архиве должны находиться достаточные полные 200-секундные фрагменты.
2. Временная разметка и повторяемость цикла должны быть подтверждены фактическими временными метками и `phase_alignment_diagnostics.csv`, а не только текстом README.
3. Нужно убедиться, что тестовые окна не использовались для настройки порога.
4. Повторные варианты масок на одном окне нельзя считать независимыми сетевыми записями.
5. Если фазовое совмещение нестабильно или атака не повторяется по заявленному шаблону, экспериментальную схему необходимо пересмотреть, а не подгонять данные под ожидаемую периодичность.
6. Числа из синтетической проверки кода не являются результатами исследования и не переносятся в статью.

## 7. Что пока не включено

В этот пакет не включены PCAP-архивы. Они скачиваются отдельно из официального репозитория. До фактической обработки архивов статья остаётся методической рабочей версией; таблицы, графики и эмпирическое заключение не должны заполняться вымышленными значениями.
