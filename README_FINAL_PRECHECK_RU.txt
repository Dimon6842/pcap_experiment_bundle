ФИНАЛЬНАЯ ПРОВЕРКА ГОТОВНОСТИ К ОСНОВНОМУ ЭКСПЕРИМЕНТУ
========================================================

Это одна заключительная проверка перед основным экспериментом. Она заменяет
предыдущую цепочку отдельных аудитов. Она НЕ создаёт результаты статьи и НЕ
проводит основной эксперимент.

ЧТО ПРОВЕРЯЕТСЯ
---------------
1. Наличие четырёх архивов UTSA-2021.
2. Чтение настоящих PCAP и PCAPNG; служебные __MACOSX-файлы пропускаются.
3. Выделение обычных записей и записей SYN-атаки; SlowRead исключается.
4. Непрерывность захвата: временная шкала разрезается там, где между соседними
   пакетами разрыв больше 5 секунд. Это правило заранее фиксировано и будет
   тем же самым в основном эксперименте.
5. Создание только полных 200-секундных окон, которые не пересекают такие разрывы.
6. Наличие ожидаемого импульсного шаблона: импульсы 0,1 с с периодом 1 с в
   активной фазе 100 с, затем 100 с спокойной фазы.
7. Достаточность числа окон и независимых PCAP для сравнения классов.

ВАЖНО ОБ IP-АДРЕСАХ
-------------------
Скрипт намеренно НЕ использует IP-адреса источников. В публикации авторов UTSA
описана обработка/рандомизация IP-адресов; кроме того, IP-адрес не должен быть
признаком нашего спектрального детектора. Поэтому прежняя идея проверять все
атаки через один фиксированный IP 10.0.2.1 не используется.

КАК УСТАНОВИТЬ
--------------
1. Распакуйте этот ZIP в папку проекта:
   E:\utsa_article\pcap_experiment_bundle
   Согласитесь на объединение файлов, если Windows спросит.
2. Не удаляйте и не переносите папки .venv и data.
3. Убедитесь, что внутри data по-прежнему лежат четыре ZIP-архива:
   Benign_Only.zip, PCAPs_1.zip, PCAPs_2.zip, PCAPs_3.zip.

КАК ЗАПУСТИТЬ
-------------
Самый простой способ: дважды щёлкните файл
ПРОВЕРИТЬ_ГОТОВНОСТЬ.bat

Он автоматически использует уже созданную виртуальную среду .venv.

Если предпочитаете командную строку, откройте её в папке проекта и выполните:

  python final_preflight.py --data-dir data --out-dir final_preflight

КАК ПОНЯТЬ РЕЗУЛЬТАТ
--------------------
В конце будет один из двух статусов:

READY   — предварительная проверка пройдена; можно переходить к одному основному
          эксперименту с теми же правилами обработки.
BLOCKED — проверка обнаружила конкретные препятствия. Основной эксперимент
          запускать нельзя; причины будут перечислены в PREFLIGHT_REPORT.txt.

После завершения в папке final_preflight появятся:
- PREFLIGHT_REPORT.txt             понятный итог READY/BLOCKED;
- preflight_manifest.json          машинный итог и причины блокировки;
- preflight_capture_summary.csv    состояние каждой PCAP-записи;
- preflight_windows.csv            характеристики каждого непрерывного окна;
- preflight_attack_signature.csv   проверка периодического импульсного шаблона;
- preflight_errors.csv              ошибки чтения, если они есть;
- preflight_excluded.csv            исключённые записи (например, SlowRead).

ЧТО ОТПРАВИТЬ
-------------
Упакуйте всю папку final_preflight в один ZIP и отправьте сюда вместе с текстом
терминала. Повторно исходные PCAP-архивы отправлять не нужно.

КРИТЕРИИ ДОПУСКА (НЕ МЕНЯТЬ ПОСЛЕ ПРОСМОТРА РЕЗУЛЬТАТОВ)
-------------------------------------------------------
- все четыре требуемых ZIP-архива присутствуют;
- не менее двух прочитанных PCAP с обычным трафиком;
- не менее четырёх прочитанных PCAP с SYN-атакой;
- не менее 20 полных непрерывных окон обычного трафика из не менее чем двух PCAP;
- не менее 30 полных непрерывных окон атакующего трафика из не менее чем трёх PCAP;
- не менее трёх атакующих PCAP подтверждают импульсный шаблон: не менее пяти
  окон на файл, медианная доля SYN в ожидаемых импульсных отсчётах >= 0,10,
  устойчивость оценки фазы между окнами в пределах 0,2 с >= 70%.

Показатели предварительной проверки — только контроль качества. Они не являются результатами
исследования и не переносятся в статью. Результаты предварительной проверки
тоже не включаются в публикацию.
